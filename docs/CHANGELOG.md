## 1.7.1 — 2026-08-06

- **「复制源码」不再动 mermaid 了** —— 现在复制出来的和你的 .md 文件**逐字节一样**。

  上一版把 ```mermaid 围栏替换成了图片链接，理由是"飞书和 WPS 把 mermaid
  显示成代码块"。那是自作聪明：飞书和 WPS 本来就支持 mermaid 渲染，
  替换反而把它们自己的能力废掉了，还把可编辑的图表变成一张死图。
  更根本的是 —— 复制源码就该给源码，擅自改内容，用户拿到的就不是他那份文档了。

## 1.7.0 — 2026-08-06

- **「复制」改成复制 Markdown 源码**（按钮改名「复制源码」）。
  飞书云文档、WPS 在线文档粘进去都会自动渲染 —— 这才是可靠的做法。

  前两版试图复制"带排版的 HTML"，绕了一大圈：
  1. 第一版写 text/html + 内联样式 → WPS 好了，飞书完全没排版。
     飞书是自研 Block 编辑器，粘贴时只保留基础标签，样式被整片过滤。
  2. 第二版想「text/html 和 text/plain 各给一份，两边各取所需」。
     **这条路从根上不成立**：富文本编辑器在两种格式都存在时**一律优先取
     text/html**（实测确认），所以飞书压根不会去看我们准备的 Markdown。
  3. 现在只写 text/plain，并显式把 text/html 清空。没有 HTML 可选，
     接收方只能走 Markdown 那条路 —— 结果反而最稳，代码也少了 250 行。

  Word 不认 Markdown，但那本来就该走「导出 → Word」（真正的 Open XML 排版，
  比粘贴强得多），不需要为它单独适配剪贴板。

  mermaid 图表仍然替换成图片链接（```mermaid 围栏在两个平台都显示成代码块）。

- **工具栏左上角「MD·Word」改成「Markdown·工作台」**。
  那是这个工具最早只做「Markdown 转 Word」时的名字，早就名不副实了 ——
  现在它读文档、改文档、审阅、导出网页/PDF/Word、分享链接，Word 只是一个出口。
  而且外壳侧栏已经叫「Markdown 工作台」，两处不一致会让人以为是两个东西。
  导出的 Word 文件属性里的作者也从「MD Word Workspace」改成「Docsmith · 文匠」。

## 1.6.3 — 2026-08-06

- **「复制文档」现在飞书也能保排版了**，同时修好图表变代码的问题。

  上一版 WPS 好了、飞书没好。原因不是剪贴板写失败（那样两边都该坏），
  而是**飞书是自研的 Block 结构化编辑器，不是通用 HTML 富文本引擎** ——
  它粘贴时只保留最基础的标签，我们抄进去的内联样式被整片过滤掉。
  但飞书**会把粘进来的纯文本按 Markdown 解析**（用户实测：粘 .md 原文有排版）。

  所以改成「两份都给对的东西」：
  - `text/html` → Markdown 原文之外的那份，带内联样式，**WPS / Word / 公众号**用
  - `text/plain` → **Markdown 原文**，飞书用

  谁认哪种取哪种，不用你操心，也不用记「粘这个平台用哪颗按钮」。

  另外：mermaid 图表在两个平台上都显示成代码块（一堆 `flowchart TD` 源码）。
  现在把 Markdown 里的 ```mermaid 围栏替换成图片语法 + data URI，
  飞书和 WPS 都能直接看到图。这份文档里 17 张图全部替换成功。

## 1.6.2 — 2026-08-06

- **修好「复制文档」**：上一版粘到飞书云文档 / WPS 只有纯文字，排版全丢。

  真凶是**兜底路径**。`clipboard.write()` 在合并进外壳的文档里会被浏览器拒
  （NotAllowedError: Write permission denied），于是代码退到 `writeText(html)`
  —— 而 writeText 只写纯文本，接收方拿到的就是一坨 566KB 的 HTML 源码字符串，
  飞书把它当普通文字贴进去，所以「只是把文字粘贴过去了」。

  改法：**优先走「选中 + execCommand('copy')」**。浏览器从真实选区复制时会
  自动把 text/html 和 text/plain 一起放进剪贴板，而且不需要 clipboard 权限、
  不要求文档有焦点 —— 在这个环境里反而最可靠。clipboard API 降为第二选择，
  兜底改成只复制纯文字（绝不再把 HTML 源码当文本塞进去）。

  顺带把产出体积从 566KB 压到 362KB：不给 `<span>`（代码高亮 token）和
  `<tr>` 抄样式（它们本来就继承/不需要），并跳过 `border: 0px none rgb(...)`
  这种「其实没有边框」的噪音值 —— 光这一条就占了几十 KB。

## 1.6.1 — 2026-08-06

- **Markdown 工作台：新增「复制文档」按钮**（工具栏常驻，在「分享」左边）。
  点一下复制整篇，粘进飞书云文档、WPS 在线文档、Word、公众号编辑器，
  **看到的就是渲染后的样子** —— 标题是标题、表格有边框、代码块有底色。

  原来这个功能藏在「导出」菜单里叫「复制 HTML」，而且是坏的：
  它走 `clipboard.writeText()`，只写 text/plain，粘出来是一堆 `<h1>` 尖括号。
  现在改成写 **text/html** 这个 flavour（同时带 text/plain 兜底），
  并且把关键的计算样式**抄成内联 style** —— 飞书/WPS 会丢掉外部 CSS，
  只认内联样式，不抄的话粘过去表格没边框、代码块没底色。

  顺带处理的细节：图表转成 data URI 的图片（飞书对内联 SVG 支持不一致）、
  代码块头上那颗 Copy 按钮不跟着粘过去、不强加字体和表格宽度
  （否则会盖掉接收方文档自己的字体、或者横向溢出）。

## 1.6.0 — 2026-08-06

新增了逐页编辑和参数记忆，还建立了备份机制。

### 新功能

- **图文卡片：逐页编辑模式**
  自动分页适合「粘一篇长文就走」，但要精确控制每张卡片时它就挡路。
  现在多了一个「逐页编辑」：自己决定分几张、每张写什么、每张用什么背景，
  还能上移/下移/复制/删除。
  两种模式并存，而且能一键从自动分页的结果导入（不用从零敲）。
  某一页写超了会**明确标出来**（编辑框变色 + 状态栏提示），不会静默裁掉。
- **图文卡片：记住你的样式**
  比例、清晰度、背景、字号、模糊度、水印（文字/位置/透明度）、页码、封面、
  默认模式 —— 这 11 项下次打开还是你调好的样子。
  **不记你写的内容，也不记上传的图片**（内容属于隐私，图片会撑爆存储配额）。
  全部列进「设置 → 记住了我什么」，每一项都能单独忘掉。
- **备份机制**：双击 `scripts/backup.cmd` 就能把整个项目打包存一份。
  另外项目现在是 git 仓库了，能精确回退单个文件。见 [04-备份与还原.md](04-备份与还原.md)。

### 修的问题

- **卡片里的换行丢了**：输入两行文字，图上并成一行。
  原因是按标准 Markdown 规则把段落内换行当成了「软换行」——
  但这个工具的输入是用户自己排好的文字，换行是意图，不该被合并。
- **阅读设置记不住**：改了字号、每行宽度，重开插件就复原。
  原因是同一个设置有两个键名（面板存 `reading.*`、工作台存 `md:*`），
  存的和读的不是一个地方。老用户的旧值会自动迁移过来，不会丢。
- **整个界面的字看着不清楚、眼睛累**：三个 CSS 文件的字体栈都领头写了
  插件根本没打包的字体（Inter / Sora），于是一路退到宋体渲染界面文字。
  另外文件库里六十多处中文用了等宽字体（汉字在等宽里发虚），
  以及界面上有 8.5px 这种尺寸。都改了。
- **图表工具栏**：三颗按钮（View source / Copy PNG / Copy code）合成两颗，
  「看什么就复制什么」。
- **渲染图偏右**：居中被做了两次（CSS 的 auto margin + 画布的 transform）。
- **导出的网页里图片不能缩放**：现在带完整的画布（缩放、拖拽、适应画布）。
- **PDF/打印**：不再新开标签页，直接在面板里唤起打印框；
  另存为 PDF 的默认文件名现在是原文件名。
- **配置云存储时凭空上传文件**：一个失效的守卫导致粘贴被当成上传。
- **分享后跳到文件库整页错位、点不动**：两个叠加的问题，都修了。

### 顺带

- 卡片背景从 6 个加到 15 个（新增 9 个渐变，含两个径向）。
- 卡片预览可以点开看原尺寸（← → 翻页，Esc 关）。
- 文档正文字体、行高、底色都调过（纸白 #fcfcfb，不是纯白）。
- 新增第三档正文字体「圆体」。
