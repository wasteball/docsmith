# 连接你的云存储

Docsmith 不保管任何人的文件，也没有自己的服务器。你上传的文件，是从你的浏览器**直接**传进**你自己的**云存储空间的。所以第一次使用前，需要花几分钟把「文件存到哪里」告诉 Docsmith。连一次，以后就不用再管了。

这份文档用大白话、一步一步带你连好。遇到任何一步卡住，页面上的报错通常会告诉你差哪一步，照着改就行。

一共两种连法，任选其一：

- [通用上传接口](#通用上传接口)：**你的公司/团队已经有一个上传接口**，你只要填个地址。最省事，也最安全（密钥在服务器上，你这边什么都不用存）。
- [阿里云 OSS](#阿里云-oss)：**你自己有阿里云账号**，文件直接传进你的存储空间（Bucket）。需要在阿里云后台点几下。

---

## 打开设置的地方

浏览器右侧的 Docsmith 面板里，点左下角的**齿轮图标（设置）**，找到「云存储」一栏。下面所有操作都在这里完成。填完不用按保存键 —— 边填边存。填好后点一下「测试一下」按钮，看到绿色的「成功」就算连通了。

---

## 通用上传接口

适合：公司已经有一个「上传文件、返回链接」的接口。你不用碰密钥，只填几个地址。

需要问一下给你这个接口的同事（或看接口文档）这几件事：

| 要填的项 | 是什么 | 例子 |
| --- | --- | --- |
| **上传地址** | 接收文件的接口网址 | `https://你的服务器/api/upload` |
| **文件参数名** | 接口接收文件时用的字段名，一般就是 `file` | `file` |
| **返回链接的位置** | 接口返回的 JSON 里，哪个字段是文件链接（用点号分层） | `data.downUrl` |
| **附加参数** | 接口还要求的其他参数，一行一个，没有就留空 | `bucket = my-bucket` |
| **请求头** | 需要携带令牌时填，没有就留空 | `Authorization = Bearer xxx` |

### 「返回链接的位置」怎么填？

假设你的接口上传成功后返回这样一段：

```json
{
  "code": 0,
  "data": { "downUrl": "https://cdn.example.com/abc.png" }
}
```

那链接藏在 `data` 里面的 `downUrl`，所以这一项就填 `data.downUrl`。

如果返回的是这样（链接在数组第一个）：

```json
{ "files": [ { "url": "https://cdn.example.com/abc.png" } ] }
```

那就填 `files[0].url`。

### 常见报错

- **「接口返回的不是 JSON」** —— 上传地址多半填错了，核对一下。
- **「在返回结果的『…』里没找到链接」** —— 「返回链接的位置」填的字段名不对，对着接口实际返回的 JSON 改。
- **「连不上上传地址（CORS）」** —— 这个接口没允许浏览器扩展访问。把 Docsmith 的来源加进接口的跨域白名单，或让维护接口的同事开一下 CORS（见下方[关于 CORS](#关于-cors)）。

## 阿里云 OSS

适合：你自己有阿里云账号，想把文件直接传进自己的存储空间。

整个过程分四步：**建空间 → 建子账号密钥 → 开跨域 → 回来填表**。

### 第 1 步：建一个存储空间（Bucket）

1. 登录[阿里云 OSS 控制台](https://oss.console.aliyun.com/)。
2. 点「创建 Bucket」，起个名字（例如 `my-docsmith`），选一个地域（例如「华东1（杭州）」）。
3. 记下两样东西，等下要填：
   - **存储空间名称**：就是你刚起的名字，如 `my-docsmith`。
   - **地域**：在 Bucket 概览页能看到，形如 `oss-cn-hangzhou`。

### 第 2 步：建一个「只能传这一个空间」的子账号密钥

**不要用主账号的密钥。** 万一泄露，主账号密钥能动你所有资源。正确做法是建一个权限很小的子账号：

1. 打开[RAM 访问控制](https://ram.console.aliyun.com/users) → 创建用户，勾选「OpenAPI 调用访问」。
2. 创建成功后会给你一对 **AccessKey ID** 和 **AccessKey Secret**。**Secret 只显示这一次，务必复制保存。**
3. 给这个用户授权，只给它「往这一个 Bucket 里写文件」的权限。可以新建一个自定义权限策略，内容如下（把 `my-docsmith` 换成你的空间名）：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:PutObject", "oss:GetObject"],
      "Resource": ["acs:oss:*:*:my-docsmith/*"]
    }
  ]
}
```

### 第 3 步：给 Bucket 开启跨域访问（CORS）—— 最容易漏的一步

浏览器出于安全，默认不允许网页往别的网站传东西。所以要在你的 Bucket 上明确「允许 Docsmith 来传」。**没做这一步，测试时会报「连不上阿里云」，这不是密钥错了。**

1. 在 OSS 控制台进入你的 Bucket → 左侧「数据安全」→「跨域设置」→「创建规则」。
2. 按下面填：

| 项 | 填什么 |
| --- | --- |
| **来源（Origin）** | `*`（先用星号确认能通；想更严，改成 Docsmith 面板地址栏里 `chrome-extension://` 开头的那一串） |
| **允许 Methods** | 勾选 `PUT`、`GET`、`POST`、`HEAD` |
| **允许 Headers** | 填一个 `*` |
| **暴露 Headers** | 填 `ETag`、`x-oss-request-id`（一行一个） |
| **缓存时间** | `600` |

3. 保存。等一两分钟生效。

### 第 4 步：回 Docsmith 填表

回到设置 →「云存储」，服务选「阿里云 OSS」，把前面记下的填进去：

| 要填的项 | 从哪来 |
| --- | --- |
| **地域** | 第 1 步，形如 `oss-cn-hangzhou` |
| **存储空间名称** | 第 1 步的 Bucket 名 |
| **AccessKey ID** | 第 2 步 |
| **AccessKey Secret** | 第 2 步（只保存在你这台电脑，不上传任何地方） |
| **存放目录** | 随意，默认 `docsmith/`，方便和别的文件区分 |
| **谁能打开链接** | 「任何人」= 链接永久有效；「只有拿到链接的人」= 更安全但链接会过期 |

填完点「测试一下」，看到绿色「成功」就完成了。

### 常见报错

- **「连不上阿里云 / CORS」** —— 第 3 步没做或没生效。回去检查跨域规则，等一两分钟再测。
- **「AccessKey Secret 不对，或者地域填错了」** —— 核对 Secret 有没有复制全，地域是否和 Bucket 所在地一致。
- **「这个密钥没有上传权限」** —— 第 2 步的授权没配对，检查权限策略里的 Bucket 名。
- **「找不到这个存储空间」** —— 空间名拼写或地域不对。
- **「电脑时间差得太多」** —— 校准一下系统时间（签名对时间敏感）。

## 关于 CORS

CORS 是浏览器的一条安全规矩：网页只能往「明确允许了它」的服务器传东西。Docsmith 在浏览器里跑，所以：

- 用**阿里云**：要在 Bucket 上开跨域（第 3 步）。
- 用**公司接口**：要让接口允许来自浏览器扩展的请求。

这不是 Docsmith 的限制，是所有「浏览器直传」都躲不开的一步。做一次就好。

---

## 换台电脑 / 备份配置

设置里有「导出配置」和「导入配置」。导出会生成一个 `.json` 文件，**默认不包含密钥**（安全起见）。换台电脑导入后，把密钥重新填一次即可。

如果你想手动准备一份配置模板，仓库里的 `docs/storage-config.example.json` 就是一个带注释说明的样板，可对照它了解每个字段。
