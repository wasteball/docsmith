# 备份与还原

改坏了怎么回去。**两层保护，出事时先看第二层（更简单）。**

---

## 第一层：一键备份（推荐，不用敲命令）

双击 **`scripts/backup.cmd`**

它会把整个项目打包成一个带日期的 zip，放到项目**外面**：

```
E:\03 workbench\10-projects\_docsmith 备份\
    docsmith_v1.5.2_2026-08-06_0851.zip
```

放外面是故意的 —— 放里面的话，下次备份会把上次的包也打进去，而且删项目文件夹时会连备份一起删掉。

**看有哪些备份**：`node scripts/backup.js --list`

### 怎么还原

1. 打开 `_docsmith 备份` 文件夹
2. 找到你想回到的那个日期的 zip，解压
3. 把解压出来的文件**覆盖**回项目文件夹
4. 去 Chrome 扩展页点一下刷新

就这样，没有别的步骤。

> 这个包是验证过能完整还原的：103 个文件，解压后和原件**逐字节一致**，
> 目录结构完整，中文文件名不乱码。不是"应该能用"，是真的试过。

### 什么时候该备份

**动手改之前**。尤其是：要改好几个文件的时候、要动 `workspace.js` 这种大文件的时候、
或者你自己也不太确定改完会怎样的时候。

备份一次 2.5MB、两秒钟。不值得省。

## 第二层：Git（精确，但要敲命令）

项目已经是一个 git 仓库了。它比 zip 强的地方：能**只回退一个文件**，
还能看出每次到底改了哪几行。

日常只需要这几条：

```bash
# 我改了哪些文件？
git status

# 具体改了哪几行？
git diff

# 存一个还原点（写清楚这次干了什么）
git add -A
git commit -m "修好了字号记不住的问题"

# 后悔了，把某个文件恢复成上次存的样子
git checkout -- src/views/cards/wire-up.js

# 后悔了，全部恢复成上次存的样子（⚠ 没存过的改动会没）
git reset --hard

# 看历史
git log --oneline
```

### 回到某个更早的状态

```bash
git log --oneline          # 找到那次的编号，比如 cefe6ed
git checkout cefe6ed -- .  # 把所有文件恢复成那时候的样子
```

## 两层怎么配合

| 情况 | 用哪个 |
|---|---|
| 改之前想留个底 | 双击 `backup.cmd` |
| 改了一个文件，想撤回这一个 | `git checkout -- 那个文件` |
| 改了一堆，全想撤回 | `git reset --hard` |
| 想回到三天前的状态 | 解压那天的 zip 覆盖回去 |
| Git 也乱了、搞不清了 | 解压 zip 覆盖回去（zip 不依赖 git） |

**zip 是最后的保险。** git 可能被误操作弄乱，zip 就是一个死文件，只要还在就一定能解开。

---

## 不进备份包的东西

- `.git/`（它自己就是历史，而且会越来越大）
- `src/app/__*.html`（会话里临时生成的测试探针页，不是项目的一部分）
- `node_modules/`、`*.zip`、系统垃圾文件

`src/vendor/` **会**进包 —— 那是运行必需的库（marked、docx、KaTeX 等），
1.5MB 而已，少了它插件跑不起来。
